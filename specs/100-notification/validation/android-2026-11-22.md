## Scope

Repository tests cover server-only 30-item newest-first queries, snapshot cursor continuation, mark-one, mark-all across two full pages and an empty terminal page, network failures, account-switch rejection, preference fallback, individual field updates and mandatory BOOKING_NEW. JVM tests also cover ViewModel error/retry/account reset and verified-source routing/fallback.

UI reuses theme/font/color tokens and screen_gutter (16dp phone, 32dp w600dp). Both reference PNGs were opened directly. Settings retains the pictured groups; mixed preferences render MaterialCheckBox indeterminate state, a mixed tap enables the group, and BOOKING_NEW is disabled/checked. OS push blocking is displayed separately with an OS-settings button. Runtime permission/token/push delivery remain outside this increment.

## Instrumentation

NotificationUiTest hosts actual Fragments in a debug-only Hilt Activity, exercises nav_main, and opens the actual MainActivity notification entry/footer. Notification repositories, resolver and UID stream use fakes. Core Auth/Firestore are confined to demo-admin-repair/local modules in the isolated adminlocal package; MainActivity shell runs as a guest with fake notification data. This is UI integration evidence, not live backend notification delivery or authenticated source-access integration. Run only with the isolated configuration:

./scripts/notification/validate-device.ps1 -Variant tablet-light -SkipInstall

Repeat on a phone and a device/emulator with actual smallest width >=600dp. Captures use the target application's external files directory: notification-{screenWidthDp}dp-{theme}-inbox.png and notification-{screenWidthDp}dp-{theme}-settings.png.

- T012/T039: Firestore preference behavior is implemented; DataStore cache ownership/synchronization remains undecided. No second writable source was introduced.
- T035: booking results/reminder, drop-in and chat route; remaining types use saved detail pending contracts.

- Backend delivery/reminder/schema decisions remain blocked. No backend/schema/Rules/deployment change is made in this increment.
- Existing admin-broadcast-notification, admin-review-application and admin-revoke-owner write notification createdAt using an ISO string; _shared/firestore.ts encodes strings as stringValue rather than timestampValue. This conflicts with the Timestamp contract used by Android queries. Mixed-type ordering and malformed existing documents require producer/data normalization before live inbox integration acceptance. Android does not silently reinterpret the persisted schema; valid-contract repository behavior is tested independently.
